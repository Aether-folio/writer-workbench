# 码字工作台（DSH 版）

- 用户说“打开码字工作台 / 写作工作台”时，调用本插件的 `open_workbench`。工作台会在 DSH **右侧栏**打开「码字工作台」标签页，不会遮住对话；用户也可以点聊天输入框右侧的「✎ 码字」按钮。标签页自带关闭 ×，右侧栏可收起。
- 工作台首页是「我的书架」：没有作品时是一本空白的书，点击即可创建第一个作品；有作品时点击封面会打开该作品「正文」里最近更新的文稿，并展开文稿侧栏。书架末尾的虚线框也可以添加作品；右键作品封面可重命名作品、更改或移除封面。顶部「书架」按钮可随时回到书架；没有归入作品的散篇文稿和尚未另存的草稿也会以书的形式留在书架上。
- 用户要求检查接入时，调用 `workbench_status`。它返回版本、作品目录、数据目录、编辑器资源、页面在线状态和文稿数量；界面是否真的显示、草稿是否成功写入，以客户端实际结果为准。
- 选中正文后右键「添加到当前聊天」，在工作台弹窗填写要求后直接发送原文快照和要求（`target: active, send: true`）。Enter 发送、Shift+Enter 换行；取消不发送，失败保留内容。没有活动会话或发送接口时明确报错。
- 默认工作区为 `D:\AI-Workspace\apps\writer-workbench`，可通过 `config.workspace` 或 `WORKBENCH_WORKSPACE` 覆盖。数据统一存放在其下的 `码字工作台/`：每部作品使用 `正文/`、`设定/`、`草稿/`，兼容已有 `文稿/`；背景、码字记录、悬浮窗设置和封面在 `数据/`，覆盖前备份在 `数据/备份/`。批注只保留在当前工作台页面内存中，刷新或关闭后清空。
- 工作台只打开这个文件夹内的 UTF-8 `.md` 和 `.txt`，不会自动导入或改动作品原有的 `正文/`。用户在界面编辑后约 1.2 秒自动保存；保存冲突时保留编辑区，可另存为。
- 码字记录按北京时间分日。新增包含输入、粘贴和重写，打开已有文件不计字数；同时保留删除字数与码字/空闲时间。草稿与文稿约 1.2 秒自动保存，计时记录约每 10 秒保存，并在保存、暂停或查看日历时同步。
- 悬浮窗的「萌宠」开关与「龙娘 / 大肥鱼」选择在「悬浮窗设置 → 展示信息」中，默认关闭，保存后写入 `数据/悬浮窗.json`。
- 批注由用户在右键菜单添加，填写后进入临时列表；「全部发送到聊天」直接发送原文快照与批注，成功清除对应记录，失败保留，发送过程中新增或修改的记录保留。
- 选择正文、添加批注不等于用户要求改稿。正文由用户写，助手只在被明确要求时提供思路或修改，不得因为用户选中一段文字就自动改稿。
- 收到「【码字工作台 · AI 插入请求】」时，先调用 `get_writing_request`，按聊天中的文稿 `path` 和写作要求 `instruction` 读取隐藏的上下文、上一版文字、`requestId` 与 `generation`（草稿 path 为空）。按要求生成纯正文，再用 `publish_writing_suggestion` 回传；不要向用户复述编号或工具说明。旧版消息可沿用已有 ID。回传段落之间只用单换行，不加空白行。工作台自动显示可编辑待采纳框，不直接改写文稿。
- AI 插入及批注重生成由用户点击发送按钮或在要求输入框按 Enter 直接发送到当前聊天（`target: active, send: true`），Shift+Enter 换行。通过活动会话的原生发送接口提交请求，不连带提交现有聊天草稿或附件。失败保留请求并允许重试；宿主缺少发送接口时明确报错。待处理请求保存在 `数据/AI辅助/`，未采纳时不混入文稿，也不计入码字统计。旧轮次和已处理请求的结果会被拒绝。
