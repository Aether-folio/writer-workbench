# 码字工作台

- 用户说打开工作台时，调用本插件的 `open_workbench`。该工具同时声明全局侧栏与当前聊天面板入口。
- 用户要求检查接入时，调用 `workbench_status`。工具只能确认声明与版本，界面是否显示、草稿是否成功追加，要以客户端实际结果为准。
- 用户选中正文并点击「添加到当前聊天」后，在工作台弹窗填写对话要求，点击发送或 Enter 将原文快照和要求一起直接发送（`target: active, send: true`）；Shift+Enter 换行，中文输入法确认不误发。取消不发送，失败保留弹窗内容。宿主没有聊天扩展时明确不可用。
- 默认工作区为 `D:\AI-Workspace\apps\writer-workbench`，可通过 `WORKBENCH_WORKSPACE` 覆盖。数据统一存放在其下的 `码字工作台/`：每部作品使用 `正文/`、`设定/`、`草稿/`，兼容已有 `文稿/`；背景和每日码字记录在 `数据/`，覆盖前备份在 `数据/备份/`。批注仅保留在当前工作台内存中，不写入本地；重新加载后清空。
- 文稿侧栏只打开这个文件夹内的 UTF-8 `.md` 和 `.txt` 文件，不自动导入或改动原有 `正文/`。用户在界面编辑后自动保存；工作台未显示保存成功时，不声称内容已经落盘。保存冲突时保留编辑区，用户可另存为。
- 码字记录按北京时间分日。新增包含输入、粘贴和重写，打开已有文件不计字数；同时保留删除字数与有效/空闲时间。草稿与文稿编辑约1.2秒后自动保存，计时记录约每10秒保存，并在保存、暂停或查看日历时同步。
- “暂停”旁的“结束”立即停止计时，手动保存当前文稿或草稿与码字记录，两者成功后才显示今日进展已保存。失败时保留内容并允许重试；不清空本次统计，继续输入后恢复计时。
- “本次码字”悬浮窗提供“萌宠”开关与“龙娘 / 大肥鱼”选择，默认关闭，选择自动保存。输入时显示码字 GIF，连续 5 秒无输入、暂停或结束后显示休息 GIF；大肥鱼休息态抱一碗白饭。萌宠版本首次更新后需要重启 Codex，以加载扩展后的保存格式。
- 批注由用户在右键菜单添加，弹窗填写后进入临时列表，可再次编辑；「全部发送到聊天」将原文与批注汇总直接发送到当前聊天（`target: active, send: true`），无需在聊天窗二次发送。发送成功清除对应记录，失败保留；发送期间新增或修改的批注保留。仅选择正文或保存批注不自动触发发送。
- 收到「【码字工作台 · AI 插入请求】」时，聊天仅展示文稿和写作要求。必须先调用 `get_writing_request`，按消息原样传入文稿 `path` 和写作要求 `instruction`（草稿的 path 为空），读取隐藏的插入位置上下文、上一版文字、`requestId` 和 `generation`。生成纯正文后调用 `publish_writing_suggestion` 原样回传 ID 与轮次。不得把定位、上下文标记、工具调用说明或编号贴到聊天；不得直接写文稿文件代替回传。旧版消息已经含 ID 与轮次时可直接沿用。普通选区引用和批注不自动触发写正文。
- 回传正文的段落之间只用一个换行（`\n`），不用 Markdown 的双换行制造空白行。待采纳框与正文共用段落排版；用户在框内手动添加的空白行保留。
- AI 插入和批注重生成请求由用户点击「发送写作请求 / 发送并重新生成」或在要求输入框按 Enter 明确触发，直接发送到当前聊天（`target: active, send: true`）。Shift+Enter 换行，中文输入法确认不触发发送。失败保留请求并提供重试，不得声称发送成功。AI 内容回传后可编辑并采纳、批注重生成或不采纳。
- 「在此处用 AI 插入」在正文可编辑且宿主支持聊天时可用，无需选中文字；右键按实际点击处定位，支持段首、段中、段尾和空行。旧后台不再让菜单永久灰显，发送前检查并明确显示版本问题。
- 待处理请求与建议保存在 `数据/AI辅助/`，按文稿路径隔离，尚未采纳时不混入 Markdown/TXT 正文，也不计入码字统计。返回旧轮次、已采纳或不采纳的请求会被拒绝，不得反复覆盖。工具未加载时请提示重启客户端；不能把聊天回复冒充为已回传。
